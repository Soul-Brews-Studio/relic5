Every agent session, from every machine, in one place you can ask.

relic5 is a small hub you run yourself. Each machine sends it the Claude Code and Codex history it holds. You, and your agents in Claude Code or claude.ai, search it by the words or by the meaning, see it as a map, and read the notes your agents keep.

Use it How it works Get relic5 on GitHub

Open source (AGPL-3.0) · alpha · self-hosted · one server, your private network

Four steps, all on machines you own.

Nothing goes to a cloud service. The machines talk to the hub over your own private network.

  1. Find

    Relic Scan finds every transcript on a machine, in every home, mirror and archive.

  2. Push

    Each machine sends its messages, tool calls and thinking to the hub, one file per month, and only what changed.

  3. Index

    The hub folds a message pushed by two machines into one, builds a keyword index, and stores a vector for each message.

  4. Ask

    Search in the web page, from the command line, or let an agent call the hub's tools while it works.

Find what was said, even when you forgot the words.

Search that suggests

Before you type, the page shows what you searched lately, what is asked most and which repos were busy. After, the sessions behind the hits sit on the left and the message, in its conversation, on the right.

  • Keyword search where every word must appear, and Thai works inside words
  • Semantic search by meaning, or both blended
  • Narrow by time, who spoke, machine, repo or one session
  • Tool calls, thinking, memory notes and git commits as their own layers

See your work as a map.

Sessions placed by meaning

Every session becomes one point, placed by the average of its messages' vectors, so sessions about the same thing sit together. Colour is the repo.

  • 3D you can turn and zoom, or a flat 2D view
  • Hover to name a point; click to read it or search inside it
  • Light up sessions by name or repo; the rest dims

The notes your agents keep, as pages

Agents write one-fact memory notes: rules you set, decisions made, where things live. relic5 shows them as a feed you can filter by kind and project. Each note opens as a page with its repo, the session that wrote it, and the real file it lives in, line by line.

And the rest of the hub

  • Live: the newest messages from every machine as they arrive
  • Jobs: every push, index and embed, failures and recoveries
  • Asked: what people and agents searched, and what found nothing

Kept where you want it, sorted by whose it is.

The hub's data is plain Parquet and Lance files. Put them on a disk or in a bucket, keep a second copy, and know which home every message came from.

A disk or S3

One folder, or an s3:// prefix on any S3-compatible store you run. Searches stay fast on S3: the search index is copied to the hub's own disk.

A mirror and a switch

Keep a second copy in step on a schedule, check it file by file, and move the hub onto it at the next start.

Whose .claude

Every message knows the home it was written in: a person's own, a second home, a project's, a backup or a mirror. Filter search and sessions by home.

Your agents can ask it too.

relic5 speaks MCP. Register it once in Claude Code, or add it to claude.ai as a connector, and an agent can look up what was decided last week before it starts again.

# what an agent sends
relic_search {
  "query": "why did the backup move",
  "semantic": true,
  "horizon": "1m"
}
# → hits with the session, time, repo and a link
relic_show { "id": "relic5://2026-10/…", "before": 3 }
# → done: say what was found
relic_found { "goal": "…", "found": "…" }

Use it, step by step.

One server runs the hub; every machine with agent history pushes to it; you and your agents ask it. Names below are examples: put your own server in.

Run the hub

On one Linux server you own. Docker, host networking, data in ~/relic5 (or set an s3:// root). It answers on port 8795.

# on the server
git clone https://github.com/Soul-Brews-Studio/relic5 ~/relic5/app
cd ~/relic5/app && just up
docker exec app-serve-1 relic5 token new laptop   # once per machine

Push from each machine

Relic Scan finds the transcripts; relic5-push sends what changed, a file per month. Run it on a timer.

# on a laptop, with the token in ~/.config/relic5/token
export RELIC5_HUB=you@my-server    # ssh target
bin/relic5-push
ssh my-server 'cd ~/relic5/app && just index'

Search in the page

Open the hub in a browser on your private network: no token from the hub itself or your own tailnet devices. Search, the map, Live, Knowledge, Asked, Performance and Settings.

# any browser on your private network
http://my-server:8795/

# or from a terminal
uv run relic5 search "why did the backup move" --limit 5

Give it to Claude Code

One command per machine. On your private network no token is needed; from anywhere else send a hub token.

# on your private network
claude mcp add --transport http relic5 http://my-server:8795/mcp

# from outside, through your tunnel, with a hub token
claude mcp add --transport http relic5 https://relic5.example.com/mcp \
  --header "Authorization: Bearer $RELIC5_TOKEN"

Add it to claude.ai

Point a tunnel (Cloudflare Tunnel, for one) at the hub and set RELIC5_PUBLIC_URL. That address shows only /mcp and sign-in. claude.ai signs in with OAuth; you approve it on the hub's page with one of your hub tokens.

# claude.ai › Customize › Connectors › Add custom connector
Name   relic5
URL    https://relic5.example.com/mcp
# Continue › Add › Connect › paste a hub token › Approve
# revoke it later in the hub's Settings › Connectors

Under the hood: open formats, one small server.

No database server to run. Files you can read with any tool, two embedded engines, and a standard protocol for agents.

LanceDBsearch tables

The keyword index (BM25, with Thai split inside words) and the vector tables, one typed schema per table, checked at every build. Vector search runs as one in-memory matrix.

DuckDB + Parquetthe history itself

Each machine's messages, tool calls and thinking as Parquet, one file per month. DuckDB folds copies from two machines into one and answers the sessions, Live and the map.

S3 or a diskwhere it lives

A folder, or any S3-compatible bucket you run. On S3 the search index is copied to the hub's own disk, so searching stays as fast. A mirror keeps a second copy in step.

MCPfor agents

Fourteen tools over streamable HTTP: search, read, sessions, homes, chains of searches, tags. Claude Code with no token on your network; claude.ai through OAuth or a hub token.

Private by how it is built.

On your serverThe hub runs on one machine you own. There is no hosted version and no account.
On your networkMachines reach it over your own private network. Anywhere else needs a hub token, or an OAuth sign-in you approve, and sees only the MCP door.
Nothing leaves on its ownNo analytics, no third-party calls. Vectors are made on your own machines. Only a connector you add and approve can read it.

relic5 is open source, in alpha.

The hub's code is on GitHub under the GNU AGPL v3. Start with Relic Scan on each machine, then run the hub on one server you own; the README has the steps.
